# ข้อตกลงการทำงานในโปรเจกต์นี้

## Space Garage — ระบบยานต้นแบบ (2026-10-26)
- CombatFeedback ใน SampleScene ผูก VFX/HIT (ผู้เล่นยิงศัตรู), VFX/HIT Monster (ศัตรูยิงผู้เล่น), VFX/DMG (เฉพาะผู้เล่นยิงศัตรู) ใช้ IShipHitReceiver.TakeHit พร้อมฝ่ายผู้ยิง/จุดชน แสดงหลังเลือดลดจริง ไม่แสดงตอน Dodge อมตะหรือโดน Def กันหมด สคริปต์ DamagePopup ใช้ GUID เดิมของ DMG Prefab ที่สคริปต์หายไว้แล้ว
- EnemySpawnManager สุ่มเกิดรอบ Tag Player มีพูล ShipPartStats แยก 4 ส่วน; Enemy ไล่ยิงได้แม้นอกจอหรือกำลังเข้าจอ ไม่หยุดยิงเพื่อรอเข้ากรอบ หันเล็งผู้เล่นแยกจากทิศเคลื่อนที่ ศัตรูทุกตัวที่อยู่ด้านหน้าเลือกบินถอยหลังยิงเพื่อรักษาระยะได้ (ไม่สุ่มแยกชนิด) ไม่มีบูสต์/Dodge/บินวน Speed พื้นฐาน 10 และมี EnemyShip/Manager ตัวอย่างใน SampleScene
- Enemy ใช้กราฟิก/Material จากส่วนของผู้เล่นตามคำขอ ไม่แทน shader ทั้งชุดเอง มี EnemyAttackTelegraph เส้นเตือนก่อนยิงและ Hit Reaction แฟลช/ถอยชั่วคราว รายละเอียด Inspector และข้อจำกัดใน SpaceGarage/README.md
- ศัตรูยิงเป็นชุด 1 วินาที พัก 1.5 วินาที ปรับ Fire Burst Duration/Fire Pause Duration บน Enemy ได้ ไม่แก้ความถี่ปืนผู้เล่น; EnemyShip มี DamageHitbox แบบ Trigger แยกขนาด (4.2,1.8,4.5) ให้โดนง่าย ปืน/กระสุนยอมรับ Trigger เฉพาะที่มี ShipDamageHitbox ไม่ขยาย collider ชนจริง
- อ่าน `SpaceGarage/README.md` ก่อนแก้ระบบยาน รายละเอียดสคริปต์ การตั้งค่า และข้อจำกัดอยู่ในไฟล์นั้น
- บินแบบเครื่องบิน 3D จริง ไม่ล็อกระนาบ XZ: ยานบินไปข้างหน้าตลอดตามหัว ปล่อยปุ่มยังบินต่อ; S เชิดหัวไต่ระดับแกน Y, W กดหัวลดระดับ, A/D เอียงเพื่อเลี้ยว ไม่ใช่หันไปทิศแกนโลก คลิกซ้ายค้างยิงตามเมาส์ ไม่เปลี่ยนทิศบินยาน (อัปเดตผู้ใช้ยืนยัน 2026-10-26)
- Shift ซ้าย/ขวาค้างใช้เกจบูสต์เริ่มต้น 100 อัตราใช้ต่อวินาทีขึ้นกับ Jet ปล่อยแล้วค่อยฟื้น ไม่ใช่ระบบชาร์จ เก็บระบบบูสต์และ HUD/VFX ของบูสต์ไว้ตามผู้ใช้ยืนยันล่าสุด
- Space + A/D พุ่งซ้าย/ขวาแนวราบเท่านั้น (อิง yaw ไม่อิง pitch/roll) ระยะ 5 หน่วยใน 0.6 วินาที พร้อมหมุนหลบ 360 องศารอบแกนหน้าช้าลงเป็น 1.2 วินาที อมตะตลอดท่า คูลดาวน์ 4 วินาทีหลังจบ ยังบินหน้าต่อ กล้อง No Roll ไม่หมุนตามและค่อยไล่ตามผ่าน ShipDodgeCameraLag กด Space เปล่าไม่ทำท่า เพิ่มช่อง HUD คูลดาวน์หลบแยก ไม่แทนช่องบูสต์ (อัปเดต 2026-10-26)
- A/D เอียงลำยานทั้งชุดรวม Rigidbody/collider เพื่อเลี้ยวจริง ปล่อยค่อยคืนปีกตรง ยานบินต่อ; ปรับ Bank Angle/Bank Degrees Per Second บน ShipController ได้ ไม่ใช้ Bank Visual Root แล้ว
- ผู้ใช้ไม่ให้บินวนตีลังกา ต้องบินมีน้ำหนักและเลี้ยวช้า: จำกัด pitch ±30 องศา เพดานก้มเงย 30 องศา/วินาที เพดานเลี้ยว 45 องศา/วินาที และหน่วง steering/speed 0.4/0.6 วินาที ปรับได้บน ShipController กลุ่ม Weighted Flight Response (ยืนยัน 2026-10-26)
- ชิ้นส่วน 4 ช่อง Gun / ArmorPlate / Wing / Jet ข้อมูล ScriptableObject เลือก Slot และใส่ Part Prefab ได้ สคริปต์กลางประกอบทั้ง 4 ส่วนตอนเล่น รองรับ SetLoadout จากหน้าปรับแต่งในอนาคต
- ผู้ใช้ใส่กราฟิกเอง ยังไม่ทำหน้าปรับแต่งหรือ UI; มีเมนูสร้างชุดทดลองพร้อมกระสุนทรงกลมโดยไม่แก้ซีนเดิม
- เพิ่มตัวอย่างประกอบสำเร็จตามคำขอที่ `SpaceGarage/Examples/StarterShip/StarterShip.prefab` มีรูปทรงพื้นฐานและข้อมูลครบ 4 ส่วน; ShipController ใช้ assembledParts แบบ serialized ซ่อนเพื่อถอดชิ้น preview ก่อนประกอบจริงตอน Awake ไม่สร้างซ้ำ
- SampleScene ใช้ CinemachineCamera/Brain เดิมของผู้ใช้ตามยานแล้ว: CinemachineFollow offset (0,3,-10), LockToTargetNoRoll และ CinemachineRotationComposer เล็งยาน ผูก Tracking Target กับ root PlayerShip; รายละเอียดปรับกล้องและข้อจำกัดอยู่ใน SpaceGarage/README.md
- ShipDodgeCameraLag ถอยกล้องขณะ IsBoosting เพิ่ม 3 หน่วยจาก offset เดิม แล้วค่อยกลับเมื่อหยุดบูสต์ ปรับ Boost Extra Distance/Pullback Time/Return Time ได้ ไม่เปลี่ยน FOV และทำงานร่วมกับ Dodge lag
- HUD ใช้ ShipHUD ผูก UI ของผู้ใช้เท่านั้น แสดง HP/Boost/ความเร็ว และวัสดุที่ระบบอื่นมาร์ก ส่งผ่าน SetTrackedMaterials; ใช้ ShipMaterialData (รหัส/ชื่อ/Sprite) และแถว ShipTrackedMaterialRow แสดงรูป ชื่อ จำนวนที่มี/เป้าหมาย ไม่แสดงทั้งคลังเอง
- เอฟเฟกต์บูสต์ใช้ ShipBoostEffect ในแต่ละ Part Prefab รองรับ VFX Graph ที่ผู้ใช้ใส่เอง เปิด/ปิดตาม IsBoosting ไม่ปิด root ชิ้นส่วน ติดตัวอย่างไว้ใน JetPart.prefab พร้อม BoostEffectPoint แต่ยังต้องใส่ VFX จริง
- ShipBoostEffect มี Normal Effect Root เพิ่มสำหรับไอพ่นปกติ สลับกับเอฟเฟกต์บูสต์ (ไม่เปิดพร้อมกัน); ยานตายหรือปิด controller/ชิ้นส่วนปิดทั้งคู่ ห้ามเปลี่ยน reference VFX เดิมที่ผู้ใช้จัดไว้
- ShipGun มี Muzzle 1/2 ยิงพร้อมกัน ช่อง Projectile Prefab รับ GameObject ไม่บังคับชนิดสคริปต์ กระสุนเลือกรับค่าปืนผ่าน IShipProjectile.Initialize ได้ เก็บการย้าย reference กระสุน/ปากเดิมไว้ ห้ามล้างข้อมูลปืนที่ผู้ใช้ใส่เอง
- ยิงตามจุดใต้เมาส์ด้วย ray จาก Camera.main/กล้องจริงของ Cinemachine โดนวัตถุใช้จุดชน ไม่โดนใช้จุดไกลตามแนว ray ทั้งสองปากยิงเข้าจุดเดียวกัน ข้าม collider ยานเจ้าของและ IShipProjectile ไม่หันตัวโมเดลปืน/ยานตามเมาส์เอง

## UI — ใช้ของที่ผู้ใช้จัดไว้ (ยืนยัน 2026-10-24)
- ผู้ใช้อนุญาตให้ ShipHUD เสกแถววัสดุที่มาร์กลง Material Container จาก Material Row Prefab ของผู้ใช้แล้ว สร้าง/ซ่อน/ลบเฉพาะ instance ที่ระบบเป็นเจ้าของ ไม่แตะลูกอื่นหรือปรับ layout Container; ถ้าไม่ใส่ Container ยังใช้ array Material Rows เดิม
- ผู้ใช้ย้ำ UI จริงใช้ Canvas/UGUI: ใช้ ShipHUD บน MainUI ผูก Text/Slider/Image ของผู้ใช้ ไม่สร้างหน้าตา Canvas เอง ส่วน Toolkit เป็นตัวอย่างเท่านั้น แก้ให้ UIDocument โหลด UXML เอง/rebind root และตรวจภาพ Play Mode ยืนยันว่าขึ้นแล้ว (2026-10-26)
- ข้อยกเว้นตามผู้ใช้สั่ง 2026-10-26: ทำ HUD ต่อสู้ตัวอย่าง UI Toolkit ได้ โดยแยก GameObject CombatHUD_Example/UXML/USS ปิดหรือแทน Layout จริงได้ ไม่แก้ MainUI เดิม อ่าน SpaceGarage/UI/README.md ก่อนแก้งานนี้
- งาน UI ให้ทำเฉพาะโค้ดและผูกข้อมูลกับ panel/ปุ่ม/ข้อความที่ผู้ใช้ทำไว้ ไม่สร้างหน้าตา panel, layout, กล่องสำรอง หรือ runtime UI เอง เว้นแต่ผู้ใช้สั่งให้สร้างโดยตรง ถ้ายังไม่ผูก reference ให้แจ้งช่องที่ต้องใส่ ไม่สร้างของสำรองแทน และไม่ย้าย/ปรับขนาด/ลำดับ UI ที่ผู้ใช้จัดไว้เอง


## Room — ประสิทธิภาพ (ผู้ใช้ยืนยัน 2026-10-23)
- Room เริ่มกระตุกหลังใส่แมพห้องใหม่ ผู้ใช้ให้คงภาพเดิม ปรับได้เฉพาะโค้ด/การวาดฉาก ห้ามลด render scale/ความละเอียด/คุณภาพไฟหรือเงาแทนเอง; อนุญาตภายหลังให้เอาเส้นดำออกเฉพาะรายละเอียดรอง/ส่วนถูกบังที่ไม่สำคัญ ไม่ใช่เส้นหลักทั้งห้อง
- ผู้ใช้ไม่ต้องการ Maximize On Play: ห้ามตั้งอัตโนมัติหรือเปลี่ยนเลย์เอาต์แทนเอง. วัด FPS ต้องระบุว่า Unity เป็นแอปที่มีโฟกัสจริงหรืออยู่เบื้องหลัง และแยกภาระ EditorLoop/SceneView/Animator ออกจากเกม
- RoomRenderBatcher บน root Room รวมชุดวาดเฉพาะฉากนิ่งตอนเข้า Play พร้อมชดเชย Toon outline ตามสเกลเดิม ใช้ Material สำเนาในหน่วยความจำเฉพาะรอบเล่น ไม่สร้างไฟล์ .mat; ห้ามใช้ StaticBatchingUtility.Combine ตรง ๆ โดยไม่ชดเชย เพราะเส้นขอบหายบางลง
- รายละเอียดโมเดล Read/Write, occlusion bake, ผลวัด Play Mode และข้อจำกัดอยู่ใน Room.md หัวข้อประสิทธิภาพแมพห้องใหม่ ถ้าแก้ geometry/ตำแหน่งฉากนิ่งต้อง bake occlusion ใหม่
- RoomRenderBatcher รุ่นล่าสุดรวมเฉพาะชิ้นไม่มีเส้นเป็นกลุ่มพื้นที่3หน่วยก่อน static batching; ข้อมูล mesh เดิมทั้ง FBX และ RoomLook/Mesh_*.asset ต้องอ่านได้ เก็บ tangent เดิม. รายการปิดเส้น126ชิ้นอยู่ที่ Outline Disabled Renderers บน root Room ไม่สร้างไฟล์ Material ใหม่

- อ่านไฟล์ `.md` ที่เกี่ยวข้องก่อนแก้งาน และอัปเดตเอกสารเมื่อทำเสร็จ
- แจ้งผู้ใช้ก่อนแก้ว่าจะเปลี่ยนอะไร โดยเฉพาะวิธีเปิด/ปิด UI และแอนิเมชัน ห้ามเปลี่ยนวิธีทำโดยไม่บอก
- ทุกครั้งที่ส่งงาน ให้บอกสิ่งที่แก้ ผลตรวจและข้อจำกัด รวมทั้งระบุชัดว่าผู้ใช้ต้องตั้งค่าหรือทำอะไรเพิ่มไหม ถ้าไม่ต้อง ให้บอกว่าไม่ต้อง
- สรุปงานให้เป็นรูปธรรมทุกครั้ง: ทำอะไรไป เขียนหรือแก้สคริปต์/กราฟ/ซีน/prefab ที่ไหน เพิ่มหรือลบช่องอะไร อยู่บน component/node ใด แต่ละช่องรับข้อมูลอะไร ผู้ใช้ใส่อะไรได้ และต้องลาก/กรอก/บันทึกอะไรต่อ ระบุว่าไม่มีช่องใหม่เมื่อไม่ได้เพิ่มช่อง
- เมื่อข้อกำหนดเรื่องพฤติกรรม หน้าตา หรือตำแหน่ง UI ไม่ชัด ให้ถามผู้ใช้ก่อนทำส่วนที่ขึ้นกับคำตอบ ห้ามออกแบบหรือเปลี่ยนวิธีแทนเองโดยไม่แจ้ง โดยเฉพาะการเลือกช่อง UI ใหม่ การซ่อนด้วย alpha แทนปิด GameObject และการเพิ่มแอนิเมชันทดแทนของเดิม
- ผู้ใช้เป็นผู้กำหนดการออกแบบและพฤติกรรมเกม ถ้าคำสั่งยังไม่ระบุวิธีหรือมีหลายความหมาย ต้องถามและรอคำตอบก่อนแก้ส่วนที่ขึ้นกับการตัดสินใจนั้น ห้ามเลือกพฤติกรรมใหม่เองแล้วเพียงแจ้งว่าจะทำ การแจ้งแผนไม่ใช่การอนุมัติ เช่น คำว่าให้มอนพยายามเคลื่อนที่ ไม่ได้อนุญาตให้เพิ่มการเดินวนรอบผู้เล่นเอง ห้ามขยายขอบเขตแทนผู้ใช้ (ผู้ใช้ย้ำอย่างชัดเจน 2026-10-23 หลังเกิดซ้ำหลายครั้ง)
- อย่าสรุปว่าผลบนจอใช้ได้จากเพียงคอมไพล์ผ่านหรือ reference ถูกต้อง แยกให้ชัดว่าตรวจข้อมูล ตรวจเส้นทางแสดงผล เรนเดอร์ดูภาพ หรือทดสอบ Play Mode จริงแล้วระดับใด
- การแสดงรายละเอียดหลัง AnswerChek: ปิดแผงไว้จริง แล้วเปิดหลังหลอดกลับตำแหน่งเพื่อให้แอนิเมชันเข้าเดิมทำงาน ไม่เปิดแผงค้างแล้วซ่อนด้วย alpha และไม่เพิ่มเฟดทดแทนเอง

- ก่อนสร้างหรือปรับโครงสกิล ต้องอ่าน Skill.md และเทียบสคริปต์สกิลเดิมที่ใกล้เคียง (เช่น JugOrNot/MagicCircle) รวม lifecycle, เสียง, hit/critical VFX, ตัวคูณดาเมจ และค่าสำรองทดสอบ ถ้าความหมายโครงสร้างไม่ชัดให้ถามก่อน ไม่เขียนรูปแบบใหม่เอง
